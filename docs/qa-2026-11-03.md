# QA — card brand and date alignment

## Changes
- Full known 15/16-digit card numbers show a local brand hint; partial/unknown values use the neutral icon. This is heuristic identification, not bank validation; it never changes the submitted card number or restricts searching.
- Card-logo containers use a fixed 28px image box to avoid SVG intrinsic size overflowing a grid track.
- Dates retain native date inputs/pickers and keyboard/accessibility semantics. A centered visual label avoids inconsistent iOS native date-text positioning.

## Verified
- 21 automated tests pass (including incomplete/unknown/malformed card detection, date validation, operator adapters, archive planning, deduplication, cancellation and receipt escaping).
- Browser: empty card validation, all four brand hints, incomplete/unknown reset, quick periods, archive start, reversed date rejection, native date picker opening.
- Live seven-operator search with an authorized card: 15 transactions (14 Astra + 1 Serbaraja), JTD/BSD/Makassar/JLB empty success, Citra HTTP 502 accurately shown as an operator error.
- Filter, ascending sort, card view, select all across filters, disabled actions with no selection, preview, fit/enlarge, and PDF download.
- Export inspected visually: three valid A4 pages, no missing logos or clipped receipt content in this sample.
- Empty operator filter, cancel archive search, clear results, restore search availability and clear preview DOM.
- API QA: method, content-type, cross-site request, malformed JSON, size limit and rate limit behavior.

## Limits
- No physical iPhone was connected for testing. The iOS date fix uses a browser-independent visual layer; actual iPhone verification remains useful.
- Empty live results for the additional operators do not prove their populated receipt formats. Their adapters retain fixture-based tests; new-operator PDFs remain JejakTol recaps.
- Citra availability is an upstream issue.
